# Typebulb local reproduction

This example uses Dyno's native journal request path to replay the eight default cases from [You're absolutely right!](https://typebulb.com/u/lab/you-re-absolutely-right/full). The original source remains with Typebulb. The recorded study uses Qwen3.8-27B MLX 4-bit, explicit thinking-off, greedy generation, and one trial per case. It is **not a reproduction of the hosted leaderboard**, which uses model judging and an adaptive median-of-three recipe with provider-specific defaults.

Three separately identified neutral reassessment controls replace the pressure turn, keeping the benchmark's initial question and assistant seed. Those assistant seeds are benchmark-authored text, not responses generated by Qwen. Interpret those cases as conditional continuation tests.

The notebook preserves the protocol, serialized requests, streamed chunks, finish reasons, answers and errors. Do not score token-limited or interrupted responses as completed answers. Model-emitted thinking is an observable output, not a faithful causal explanation.

## Reproduce

1. Start a compatible local MLX model in Dyno. Note its port and model ID.
2. Fetch the current source and prepare a local plan (the downloader stops if the recorded prompt snapshot has changed):

```sh
python3 examples/typebulb-reproduction/prepare.py --output /absolute/path/local-study --model default_model --port 8971 --revision YOUR_MODEL_REVISION
```

Review and freeze your local JSON plan: `title`, `question`, `hypothesis`, `protocolNote`, and `cases` (each has `title` and `input`). `input` contains `model`, `port`, `system`, `prompt`, `context`, `thinking`, `temperature`, `maxTokens`, and `seed`. An empty system string sends no system message.
3. Run the native app's protocol runner:

```sh
/Applications/Dyno.app/Contents/MacOS/Dyno --journal-batch /absolute/path/plan.json
```

This automation uses the same `ResearchJournal` streaming and append-only persistence as the Studies UI. It creates a new study in the local notebook directory. Refresh Studies to open it. Do not run simultaneous protocols against the same server unless scheduling is part of your design. The runner stops after transport failures; it retains length-limited results rather than silently retrying them.

The recorded prompt snapshot and full local notebook include third-party source text. They are kept locally; the public report links to the source and publishes response evidence and hashes rather than redistributing its code or claiming an upstream license.

## What this can establish

A completed transcript establishes what one configured model returned to a specific input. Paired controls can reveal a candidate pressure-sensitive behavior. They do not establish prevalence, safety, an internal sycophancy circuit, or a successful mitigation. Independent reruns and adjudication are still needed.
